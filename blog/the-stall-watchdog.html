The watchdog that stopped thirty minutes of silence

A child that produces nothing for three minutes is wedged. Detecting that is not obvious.

  • Nov 17, 2026
  • 1 min read
  • Development

An agent that fails loudly is easy to handle. An agent that simply stops producing output is worse, because nothing in your code has errored. The process is alive, the socket is open, and the child is doing something you cannot see.

In the delegation server for let-me-code, the default ceiling for a single child message was thirty minutes. A wedged child would burn the entire budget before anyone learned it was stuck.

Fingerprinting the message stream

The fix is a watchdog. On every poll the client fingerprints the child's message stream. When that fingerprint stops changing for stallMs, the child is treated as wedged: the session is interrupted, a log entry is written with stalled: true, and the ticket is retried once in a fresh session. 

{
  "timeouts": {
    "healthMs": 5000,      // wait for the server to answer a health check
    "messageMs": 1800000,  // hard ceiling for one child message
    "stallMs": 180000    // no visible progress this long = wedged
  }
}

The three numbers do different jobs. messageMs is the hard ceiling, the one that eventually ends any run. stallMs is the early warning, and it is the one that actually saves you time because it fires while there is still budget left to retry.

Why retry once, not forever

One retry in a fresh session handles the common transient case: a provider hiccup, a malformed tool call, a dropped connection. A second stall blocks the ticket and reports what was tried. Retrying indefinitely converts one confusing failure into a slow, expensive, confusing failure.

Silence is not a status. Silence is the absence of a status, and it has to be treated as an error.

The general lesson

Any supervisor of another process needs a definition of progress that is narrower than "still running". Liveness checks tell you the process exists; they do not tell you it is doing anything.

Settings and the rest of the configuration are documented at the documentation site.
