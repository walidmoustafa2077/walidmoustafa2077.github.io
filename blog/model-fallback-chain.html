When a model name goes stale

A dead provider string should degrade a job, not kill it.

  • Nov 16, 2026
  • 1 min read
  • Development

Model identifiers rot. A provider renames a model, retires a preview build, or stops serving a region. If your agent config hardcodes one name, the day it changes every delegated job fails with an error that looks like a bug in your code.

let-me-code resolves the model for each call from DELEGATE_CONFIG.json, most specific first. 

{
  "defaultModel": "gemini-proxy/flash",
  "fallbackModel": "ollama/deepseek-v4.1-flash:cloud",
  "allowCustomModel": true,
  "agents": {
    "senior-dev": {
      "model": "gemini-proxy/flash",
      "fallback": "ollama/deepseek-v4.1-flash:cloud",
      "allowCustom": true
    },
    "junior-dev": {
      "model": "ollama/deepseek-v4.1-flash:cloud",
      "allowCustom": false
    }
  }
}

Resolution order, per call: agent model → defaultModel → agent fallback → fallbackModel.

The retry that matters

On an unknown-model error, the job retries the same message against the next candidate model. That is the whole trick. A stale provider name degrades the run instead of ending it.

This is not the same as a general retry. Retrying the identical request against the identical model would just fail again. Retrying against the next candidate works because the failure is about the model, not the message.

Pinning is a deliberate choice

let-me-code init --model <id> writes the id as defaultModel, as each agent's model, and onto every factory agent in opencode.json. Without that flag nothing is pinned, and every agent inherits the default model of the opencode session it runs in.

Pinning buys reproducibility. Falling back buys uptime. Knowing which one you asked for is the whole design.

The per-agent allowCustom flag also acts as an allowlist: passing a model to delegate_task is rejected unless the agent or allowCustomModel permits it. Cheap model for mechanical work, expensive model where it counts, and no way for a caller to quietly override the expensive one.
